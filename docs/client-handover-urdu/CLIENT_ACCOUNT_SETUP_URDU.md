# کلائنٹ اکاؤنٹ سیٹ اپ گائیڈ (Client Account Setup - Urdu)

یہ گائیڈ بتاتی ہے کہ ویب سائٹ چلانے/لائیو کرنے کے لیے کن اکاؤنٹس اور سیٹ اپ کی ضرورت ہو سکتی ہے، اور کن چیزیں اس پروجیکٹ میں/کلائنٹ کی طرف سے درکار ہیں۔

## 1) ایڈمن اکاؤنٹ (Admin Account)
- پہلا Super Admin اکاؤنٹ `/admin/setup` سے بنتا ہے (جب کوئی ایڈمن موجود نہ ہو اور سرور سیٹ اپ مکمل ہو)۔
- ضروری: `ADMIN_SETUP_SECRET` سرور env (ایک وقتی راز)۔ قدر خفیہ رکھیں۔
- پہلا اکاؤنٹ بننے کے بعد `/admin/login` سے لاگ ان کریں۔
- MFA/سیکیورٹی سیٹنگز: `ACCOUNT_SECURITY_GUIDE_URDU.md` دیکھیں۔

کلائنٹ ذمہ داری:
- مضبوط پاس ورڈ اور MFA (اگر استعمال ہو) محفوظ رکھنا۔
- مجاز عملے کے لیے الگ اکاؤنٹس/رولز دینا (Super Admin کے مطابق)۔

## 2) ڈیٹا بیس اکاؤنٹ/سروس (Database)
- پروجیکٹ PostgreSQL + Prisma استعمال کرتا ہے۔
- ضروری سرور env میں `DATABASE_URL` (حقیقی قدر خفیہ)۔
- لوکل/پروڈکشن ڈیٹا بیس سیٹ اپ، مائیگریشنز، رسائی، اور بیک اپ کلائنٹ/آپریٹر کی ذمہ داری (پروجیکٹ دستاویزات کے مطابق)۔

## 3) ہوسٹنگ/ڈومین اکاؤنٹ (Hosting & Domain)
- پروڈکشن ہوسٹنگ، ڈومین، DNS، SSL/HTTPS، اور `NEXT_PUBLIC_SITE_URL` جیسی عوامی سیٹنگز کلائنٹ کی منظوری/اکاؤنٹ پر منحصر ہیں۔
- یہ ریپو خود بخود ڈومین یا ہوسٹنگ اکاؤنٹ نہیں بناتی۔

## 4) ادائیگی اکاؤنٹس (Payment Accounts)
- دستی/manual طریقے: **Bank Transfer (BankIslami وغیرہ جیسا کنفیگر ہو)** اور **Easypaisa**۔
- گاہک کو دکھنے والی اکاؤنٹ تفصیلات سرور env/config سے آتی ہیں (مثلاً بینک/ایزی پیسہ نمبر، اکاؤنٹ ہولڈر نام، ڈسپلے نام — env نام env-check/پروجیکٹ کنفیگ میں درج ہیں؛ اقدار خفیہ رکھیں)۔
- ایڈمن Payment Verification ہمیشہ اصل اکاؤنٹ اسٹیٹمنٹ/ریکارڈ سے کرے۔

کلائنٹ ذمہ داری:
- درست بزنس اکاؤنٹس فراہم/کنفیگر کرنا۔
- اکاؤنٹس کی ملکیت/رسائی محفوظ رکھنا۔
- وصولی کی باقاعدہ تصدیق کرنا۔

## 5) میڈیا/اسٹوریج (اگر درکار ہو)
- پروڈکٹ تصاویر اپلوڈ کے لیے اسٹوریج ٹوکن/سروس درکار ہو سکتی ہے (مثلاً `BLOB_READ_WRITE_TOKEN` env نام پروجیکٹ چیکس میں موجود ہے)۔
- کلائنٹ/آپریٹر متعلقہ سروس اکاؤنٹ بنائے اور خفیہ ٹوکن سرور env میں رکھے۔

## 6) سپلائر اور کورئیر اکاؤنٹس/تعلقات
- سپلائرز: حقیقی سپلائر ریکارڈز، شناخت/معاہدہ/تصویر حقوق/قیمت و اسٹاک تصدیق ایڈمن میں درج کریں۔
- کورئیرز: کمپنی اکاؤنٹ/شرائط/زیورات قبولیت کی تحریری تصدیق حاصل کریں، پھر Shipping سیٹنگز میں ریکارڈ کریں۔
- یہ کاروباری اکاؤنٹس/معاہدے کلائنٹ کی ذمہ داری ہیں؛ پروجیکٹ انہیں فرض نہیں کرتا۔

## 7) سرور env اور سیکیورٹی سیٹنگز (ناموں کی سطح پر)
پروجیکٹ/env-check میں ظاہر ہونے والے اہم env ناموں کی مثالیں (اقدار یہاں شامل نہیں):
- `DATABASE_URL`
- `NEXT_PUBLIC_SITE_URL`
- `CHECKOUT_DRAFT_SECRET`
- `BLOB_READ_WRITE_TOKEN`
- `ADMIN_MFA_ENCRYPTION_KEY`
- `ADMIN_MFA_CHALLENGE_SECRET` (اختیاری)
- `ADMIN_SETUP_SECRET` (ایک وقتی، بعد میں ہٹائیں/روٹیٹ کریں)
- `RATE_LIMIT_PROVIDER`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (پروڈکشن ریٹ لمیٹنگ کے مطابق)
- ادائیگی متعلق env نام (سرور سائیڈ، UI میں ظاہر نہیں)

چیک کمانڈ (انگریزی): `npm run env:check` / `npm run env:check:dev`

## 8) خلاصہ - کلائنٹ کو کیا فراہم کرنا ہے
- اصلی بزنس معلومات (اسٹور نام/رابطہ/پالیسی متن)
- تصدیق شدہ سپلائرز اور مصنوعات کا ڈیٹا
- ادائیگی اکاؤنٹس اور ان کی تصدیق کا عمل
- ہوسٹنگ/ڈومین/ڈیٹا بیس/اسٹوریج اکاؤنٹس (ضرورت کے مطابق)
- بیک اپ/بحالی اور لانچ سے پہلے حتمی منظوری
